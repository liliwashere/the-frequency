✦ Must read
🚆
Railway (Jake Cooper) · blog.railway.com · May 19–20
Incident Report: how an 8-hour outage cascaded from one cloud account suspension
On May 19, Google Cloud incorrectly suspended Railway's production account, and an 8-hour platform-wide outage followed — despite a multi-AZ, multi-cloud mesh ring with HA fiber between their Metal, GCP, and AWS deployments. The honest part: workload discoverability was still unintentionally tied to GCP, so a single upstream action cascaded everywhere. Founder Jake Cooper (Canada) takes full ownership rather than hiding behind Google. The eerie timing: Latent Space had just published a Railway "agent-native cloud" deep-dive recorded before the outage. Read the report as a case study in how multi-cloud can still single-thread.

🔬 Models, papers & sharp ideas
✦ Idea of the week
🧵
Hugging Face · huggingface.co/blog · ~May 20
Software Forgets: Agent Traces Are the Memory
The premise: software is hard to explain because the reasoning behind decisions evaporates. The original author forgets why; commit messages and PR descriptions capture a thin slice; the rest lives in someone's head until they leave.

The HF team's move: their coding agent writes every session to a shared bucket, so future agents and human reviewers can pull the exact trace that produced a change. Agent traces become the durable institutional memory the codebase never had. A clean reframe of "memory" away from vector stores and toward execution history.

Railway · blog.railway.com · May 19–20
Platform risk is back: when your cloud provider can switch you off
The Railway outage wasn't a bug — Google Cloud suspended a paying customer's production account, and a whole platform went dark for 8 hours. For any business built on someone else's infrastructure, that's the uncomfortable headline: provider concentration is an existential risk, not a footnote in a vendor agreement.

Worth studying for the second-order effect too — the HN and self-hosting conversations that spiked right after, as founders re-priced their dependency on a single hyperscaler.
